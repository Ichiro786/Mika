## A. Executive Summary

### 1. Repository Verification & Build Foundation

Mika is a native, on-device Android AI agent application written in Kotlin and Jetpack Compose that executes multi-step tasks across third-party Android applications (on a hidden background virtual display via wireless debugging / ADB shell helper or Root), an in-app desktop-class WebView browser (controlled via Chrome DevTools Protocol), and a per-conversation Alpine Linux 3.22 PRoot sandbox (`aarch64` / `arm64-v8a`) ([Mika Repository Overview](https://github.com/wangzan101/mika), [Sandbox Architecture](https://github.com/wangzan101/Mika/blob/main/tools/sandbox/README.md)).

### 2. Current UI/UX Maturity, Strengths, Weaknesses, and Redesign Feasibility

#### Overall Maturity Assessment
Mika exhibits **high functional completeness and systems engineering maturity** (scoring 8.7/10 overall code health on [Repowise Code Health](https://repowise.dev/repo/wangzan101/mika/code-health) across 1,567 files and 139.1K lines of code), paired with a **utilitarian, developer-centric UI layer** that has grown rapidly through feature additions (785+ commits since late October 2026) ([Mika Commit History](https://repowise.dev/repo/wangzan101/mika/commits)).

#### Core Strengths
1. **Strict Engine-to-UI Decoupling (`PackageDependencyTest`):** The core agent loop, tool registry, prompt assembly, and capability interfaces reside in `:core` (`core/src/main/kotlin/com/wangzan101/mika/core/`), completely free of Android UI dependencies and guarded by `PackageDependencyTest` ([Roadmap & Architecture](https://github.com/wangzan101/Mika/blob/main/docs/dev/roadmap.md)). This makes a full UI/UX overhaul in `:app` exceptionally safe.
2. **Sophisticated Multi-Surface Agent Interaction:** Unlike basic chat wrappers, Mika already implements a live background virtual-screen PiP preview (`PipPhysics.kt`, `PipSizing.kt`, `ScreensScreen.kt`), a system-wide floating edge overlay (`capsule/CapsuleController.kt`, `CapsuleDock.kt`, `CapsuleCardContent.kt`), human-in-the-loop authentication/payment handoff (`takeover/TakeoverActivity.kt`, `confirm/ConfirmationNotifier.kt`), and a rich Hold-to-Talk gesture state machine (`ui/VoiceHold.kt`, `voice/HoldToTalk.kt`) ([Detailed Features](https://github.com/wangzan101/Mika/blob/main/docs/features.en.md)).
3. **Traceability & Transparency:** Every agent run records step-by-step actions, screenshots, sources (`SourceScreen.kt`), OTLP traces (`RunTimelineScreen.kt`, `RunTraceSection.kt`), and granular token accounting (`UsageScreen.kt`, `ChatTokens.kt`) ([Features — Everything is Traceable](https://github.com/wangzan101/Mika/blob/main/docs/features.en.md)).
4. **Comprehensive Localization Infrastructure:** Supports 11 UI languages (Simplified Chinese, Traditional Chinese, English, Arabic, Persian, Japanese, Korean, Spanish, Portuguese, Russian, Indonesian) with automated placeholder and CLDR plural verification via `StringResourcesTest` and `tools/i18n/translations.py` ([Contributing Guide](https://github.com/wangzan101/Mika/blob/main/.github/CONTRIBUTING.zh-CN.md)).

#### Core Weaknesses
1. **Flat Custom Navigation Stack (`ui/Navigation.kt`):** Navigation relies on a custom `mutableStateOf`-backed `NavStack` and flat `Route` enum rather than `androidx.navigation:navigation-compose` or predictive-back-aware `AnimatedContent` transitions. Screen changes snap or crossfade abruptly without spatial hierarchy, shared elements, or Android 14/15 predictive back gesture previews (`OnBackAnimationCallback`).
2. **Pre-Expressive Material 3 Token System (`ui/theme/`):** While `MikaTheme` (`Theme.kt`) and `MikaType` (`Tokens.kt`) wrap Material 3 (`1.3.1`), typography uses ad-hoc iOS-like point sizes (`LargeTitle = 28.sp`, `Title = 17.sp`, `Body = 15.5.sp`, `Caption = 13.sp`, `Hint = 12.sp`) without custom variable font families, optical sizing, or Material 3 Expressive display/headline tokens. Color tokens (`Colors.kt`, `SkinAccent.kt`) lack a dedicated true-black (`#000000`) AMOLED surface hierarchy with tonal elevation steps, and rely on optional background skin images (`SkinImage.kt`) that degrade legibility and visual calm.
3. **High-Churn Monolithic Screen Files:** Static complexity analysis flags `ui/ModelSetupViewModel.kt` (16 commits/90d), `ui/ModelSetupScreen.kt` (14 commits/90d), `ui/ModelsScreen.kt` (13 commits/90d), `ui/PhoneSetupScreen.kt` (deeply nested 6-step wizard logic), and `ui/ChatDrawer.kt` (7 commits/90d) as high-churn hotspots where UI layout, state orchestration, and domain validation are tightly interleaved ([Repowise Hotspots](https://repowise.dev/repo/wangzan101/mika/code-health)).
4. **Conflated Conversation & Agent Execution Density in `ChatScreen.kt`:** The main chat view simultaneously hosts the top bar with token counters, conversation search bar, inline expandable tool steps, floating live virtual-screen PiP, queued message banners, quote/branch banners, attachment strip (`ChatAttachments.kt`), reasoning tier selector (`ReasoningControl.kt`), follow-up bar (`FollowUpBar.kt`), and voice-hold overlay (`VoiceHold.kt`). Additionally, active issues document UX friction during task execution, such as inability to attach images while a task is running ([Issue #482](https://github.com/wangzan101/Mika/issues)) and hidden thinking-tier rows when custom OpenAI-compatible gateways omit tier metadata ([Issue #562](https://github.com/wangzan101/Mika/issues)).

#### Redesign Feasibility toward a Claude Duet-Inspired Experience
**Feasibility Rating: High (9/10).** Because `:core` is strictly isolated from `com.wangzan101.mika.ui.*` and `:app` already exposes reactive state via `ChatViewModel`, `MemoryViewModel`, `RunTimelineViewModel`, `ModelSetupViewModel`, and `SourceViewModel`, Mika can be transformed into a calm, tactile, Material 3 Expressive personal-agent experience inspired by Claude Duet **entirely within `:app` (`ui/`, `capsule/`, `res/`)** without breaking the agent execution loop, ADB shell helper, WebView automation, or PRoot Linux sandbox.

## C. Design-System & Visual Design Audit (Material 3 Expressive Evaluation)

### 1. Current Design System Architecture (`ui/theme/`)

Mika centralizes its theme primitives across six files in `app/src/main/java/com/wangzan101/mika/ui/theme/`:
* **`Theme.kt` (`MikaTheme`)**: Wraps `androidx.compose.material3.MaterialTheme` (`1.3.1`), supporting three appearance modes (`Follow system`, `Always light`, `Always dark`, added in `v0.1.32`) and applying custom light/dark color palettes alongside user-selected skin accents (`SkinAccent.kt`) and optional full-screen background images (`SkinImage.kt`) ([Releases v0.1.32](https://github.com/wangzan101/Mika/releases)).
* **`Tokens.kt` (`MikaType`)**: Defines custom text style tokens outside the standard Material 3 `Typography` scale:
  * `LargeTitle`: `28.sp`
  * `Title`: `17.sp`
  * `Body` / `BodyStrong`: `15.5.sp`
  * `Value`: `15.sp`
  * `Caption`: `13.sp`
  * `Label`: `13.sp`
  * `Hint`: `12.sp`
* **`Colors.kt` & `SkinAccent.kt`**: Defines semantic surface, text, border, status (running/orange-needs-you/success/error), and customizable accent tokens.
* **`Icons.kt`**: Centralizes vector icon definitions used across navigation, chat actions, and tool indicators.
* **`UpdateGlassSurface.kt`**: Provides translucent/glassmorphic card styling for floating capsules and update/confirmation surfaces.

### 2. Evaluation Against Modern Android & Material 3 Expressive Principles

| Audit Dimension | Current Implementation State in Mika | Material 3 Expressive Gap & Usability Impact |
| :--- | :--- | :--- |
| **1. Typography Hierarchy & Consistency** | `Tokens.kt` (`MikaType`) defines 7 flat sizes (`28.sp`, `17.sp`, `15.5.sp`, `15.sp`, `13.sp`, `12.sp`) modeled after iOS Human Interface Guidelines (`17pt` nav title, `28pt` large title) rather than Android Material 3 (`displaySmall`, `headlineMedium`, `titleLarge`, `bodyLarge`, `labelMedium`). Both `Caption` and `Label` share `13.sp` without distinct letter-spacing (`em`) or weight contrast. | **Usability Impact:** In long multi-step agent logs (`RunTimelineScreen.kt`) and dense settings screens (`ModelsScreen.kt`), `17.sp` section titles and `15.5.sp` body copy lack sufficient typographic scale contrast, forcing users to read every line rather than scanning headers. Adopting an expressive editorial display face (or variable sans/serif pairing) with clear weight/tracking differentiation (`headlineSmall` 24sp SemiBold, `titleMedium` 16sp Medium, `bodyLarge` 16sp Regular with `24.sp` line height, `labelSmall` 11sp Medium tracked `+0.04em`) dramatically improves scan speed. |
| **2. Color System, Dynamic Color & AMOLED Quality** | `Theme.kt` and `Colors.kt` provide light/dark palettes plus manual `SkinAccent.kt` presets and `SkinImage.kt` background wallpaper overlays. Dark mode uses dark gray surfaces rather than a structured true-black (`#000000`) AMOLED hierarchy, and does not integrate Android 12+ Material You dynamic color (`dynamicDarkColorScheme` / `dynamicLightColorScheme`) with harmonized semantic status tokens. | **Usability Impact:** On modern OLED/AMOLED flagships, dark gray backgrounds consume unnecessary display power during long background agent runs (when the screen stays awake per `v0.1.33`/`v0.1.34`) and reduce contrast for floating PiP previews. Moreover, user-supplied `SkinImage.kt` wallpapers behind dense Markdown tables and step logs introduce luminance noise that violates WCAG 4.5:1 text contrast. A true-black `#000000` (`surfaceDim` / `background`) canvas with stepped tonal containers (`#0E0E11` `surfaceContainerLow`, `#16161B` `surfaceContainer`, `#22222A` `surfaceContainerHigh`) eliminates visual clutter and saves power during extended agent monitoring. |
| **3. Shapes, Corners, Surfaces & Elevation** | Cards, dialogs (`PlanEditorDialog.kt`, `TokenBudgetDialog.kt`), and message bubbles use uniform rounded rectangles (`RoundedCornerShape`) and 1dp border strokes or flat alpha fills (`UpdateGlassSurface.kt`), without M3 Expressive shape morphing (e.g., morphing buttons/chips from pill `50%` to squircle `16.dp` on press/selection). | **Usability Impact:** Uniform corner radii make interactive controls (action chips, expandable tool cards, stop buttons) indistinguishable from static info containers. Expressive shape morphing (animating corner radius on press/active states) provides immediate tactile confirmation of touch registration—critical when interrupting a live agent. |
| **4. Spacing, Alignment & Visual Density** | Recent releases (`v0.1.34`, `v0.1.35`) consolidated Settings (`SettingsSubPages.kt`) and compacted `"Reasoning"` and `"Context compaction"` into action rows (`ReasoningControl.kt`). However, `ChatScreen.kt`, `ModelsScreen.kt`, and `PhoneSetupScreen.kt` remain visually dense, packing multiple status badges, token counters, and action links into tight vertical stacks. | **Usability Impact:** High cognitive load during onboarding and task monitoring. Users confronting the 6-step `PhoneSetupScreen.kt` or multi-role `ModelsScreen.kt` face walls of explanatory text (`PhoneSetupCopy.kt`) instead of progressive disclosure. |
| **5. Iconography** | `ui/theme/Icons.kt` provides functional vector icons, and `v0.1.35` removed the redundant leading mic icon from the centered voice-input hint. However, tool execution steps in `ChatRows.kt` and `RunTimelineScreen.kt` lack distinct, color-coded semantic iconography differentiating Phone UI actions (`tap`, `type`, `scroll`), Browser actions, Sandbox shell execution, and Memory lookups. | **Usability Impact:** Users scanning a 30-step agent run cannot visually distinguish whether Mika is tapping a third-party app, reading a web page, or executing a Python script in PRoot without reading the text label of every step. |
| **6. Navigation Bars, Top App Bars & Drawer** | Uses a single `ModalNavigationDrawer` (`ChatDrawer.kt`) as the primary global navigation hub for 12+ destinations, paired with a dense custom top bar on `ChatScreen.kt` (drawer toggle, title, cumulative token pill `ChatTokens.kt`, search toggle `ChatSearch.kt`, new chat). | **Usability Impact:** Hiding core personal-agent surfaces (`Personal`, `Plans`, `Memory`, `Screens`) inside a hamburger drawer alongside conversation history makes Mika feel like a legacy utility app rather than a cohesive personal agent. Furthermore, swipe-from-left-edge to open `ModalNavigationDrawer` directly conflicts with Android's system-wide edge-swipe back gesture. |
| **7. Cards, Lists, Chips, Dialogs & Bottom Sheets** | `v0.1.35` unified in-app dialogs to Mika's visual style with Markdown-rendered notices. However, heavy configuration flows (`PlanEditorDialog.kt`, `TokenBudgetDialog.kt`, `PersonalReplayDialog.kt`) are rendered inside centered modal dialogs rather than full-height or adaptive `ModalBottomSheet` surfaces. | **Usability Impact:** Centered dialogs with multiple text inputs and time pickers (`PlanEditorDialog.kt`) suffer from severe vertical cramping when the soft keyboard (IME) opens, forcing awkward nested scrolling. |
| **8. Text Fields & Message Composer** | The bottom composer in `ChatScreen.kt` combines text input, Hold-to-Talk (`VoiceHold.kt`), attachment strip (`ChatAttachments.kt`), quote/follow-up banner (`FollowUpBar.kt`), and reasoning controls (`ReasoningControl.kt`). Currently, when a task is running, users can type follow-up instructions ("interjections"), but cannot attach images to the composer ([Issue #482](https://github.com/wangzan101/Mika/issues)). | **Usability Impact:** Blocking image attachments during active runs prevents users from sending visual clarifications (e.g., a screenshot or QR code) when Mika asks a follow-up question mid-task. |
| **9. Edge-to-Edge, Window Insets & Keyboard (IME)** | `targetSdk = 35` enforces edge-to-edge on Android 15. `CapsuleController.kt` recently received multiple fixes (`v0.1.35`, `#524`, `4ade16b`) so the floating capsule card no longer resizes erratically with IME candidate rows or jumps on release. Inside `MainActivity`, however, IME transitions are jump-cut rather than smoothly synchronized via `WindowInsetsAnimationCompat` / `Modifier.imePadding()`. | **Usability Impact:** Opening and closing the keyboard in `ChatScreen.kt` causes abrupt layout jumps in the `LazyColumn` message list rather than a 120Hz frame-synchronized slide. |
| **10. Small-Screen & Large-Screen Adaptability** | Layouts in `ui/` are designed exclusively for portrait phone viewports (`width < 600.dp`). Even the floating PiP (`PipSizing.kt`) and `ChatDrawer.kt` assume single-column portrait geometry. | **Usability Impact:** On foldables (e.g., Pixel Fold, Galaxy Z Fold) and tablets, `ChatScreen.kt` stretches message bubbles and Markdown tables across the entire unfolded canvas instead of splitting into a side-by-side **Conversation + Live Background Screen / Run Timeline** two-pane workbench. |

### Detailed Findings Specifications

#### `UI-001` — Custom `NavStack` Bypasses Jetpack Navigation, State Restoration, and Predictive Back
* **Severity:** Critical
* **Category:** Navigation, State Preservation & Motion
* **Affected Screen / Component:** Global App Navigation (`NavStack`, `Route`)
* **Exact File Path & Line References:** [`app/src/main/java/com/wangzan101/mika/ui/Navigation.kt`](https://github.com/Ichiro786/Mika/blob/main/app/src/main/java/com/wangzan101/mika/ui/Navigation.kt) (lines 1–120); [`app/build.gradle.kts`](https://github.com/Ichiro786/Mika/blob/main/app/build.gradle.kts) (lines 95–130); [`gradle/libs.versions.toml`](https://github.com/Ichiro786/Mika/blob/main/gradle/libs.versions.toml) (lines 21–50).
* **Evidence from Source Code:** Inspection of `gradle/libs.versions.toml` (lines 21–50) and `app/build.gradle.kts` (lines 95–130) confirms that neither `androidx.navigation:navigation-compose` nor `androidx.compose.animation:animation` shared-element navigation is included. Instead, `Navigation.kt` implements a custom `NavStack` backed by Compose `mutableStateOf` over the `Route` enum (`Chat`, `Personal`, `Settings`, `Memory`, `Plans`, `Browser`, `Files`, `Run`, `Source`, `PhoneSetup`, `Models`, `Usage`) and intercepts back presses via `NavStack.back()`.
* **User-Visible Impact:**
  1. **No Predictive Back Gesture:** On Android 14 and Android 15 (`targetSdk = 35`), swiping back from `Settings`, `RunTimelineScreen`, or `MemoryScreen` does not render the system-level predictive back scale/peek animation, breaking platform expectations.
  2. **Lost Scroll & Sub-Screen State on Configuration Change / Process Death:** Because `NavStack` holds in-memory state without per-destination `SaveableStateHolder` + `ViewModelStoreOwner` scoping, rotating the device or surviving background process death while viewing a deep destination resets navigation or loses scroll positions in child screens.
  3. **Abrupt Screen Cuts:** Switching routes replaces the composition tree without spatial shared-axis or container-transform transitions.
* **Recommended Correction:** Wrap `NavStack` destinations in `SaveableStateHolder` and `AnimatedContent` driven by `SeekableTransitionState` wired to `BackHandler` / `PredictiveBackHandler` (or migrate to type-safe `androidx.navigation:navigation-compose:2.8.x+` with Kotlin Serialization routes, which is already in the classpath via `kotlinx-serialization-json:1.7.3` at `libs.versions.toml` line 9).
* **Regression Risk:** Low — `Route` enum values and deep-link triggers from `MainActivity.kt` and `MikaSelfTools` ("Allow Mika to operate its own UI") can preserve their exact route signatures.
* **Confidence:** Confirmed.

#### `UI-002` — Composer Blocks Image & File Attachments While a Task Is Running
* **Severity:** Critical
* **Category:** Chat & Agent Experience (Composer Workflow)
* **Affected Screen / Component:** `ChatScreen` Input Composer & Attachment Strip
* **Exact File Path & Line References:** [app/src/main/java/com/wangzan101/mika/ui/ChatScreen.kt](https://www.google.com/search?q=https://github.com/Ichiro786/Mika/blob/main/app/src/main/java/com/wangzan101/mika/ui/ChatScreen.kt) (composer action bar section); [app/src/main/java/com/wangzan101/mika/ui/ChatAttachments.kt](https://www.google.com/search?q=https://github.com/Ichiro786/Mika/blob/main/app/src/main/java/com/wangzan101/mika/ui/ChatAttachments.kt); [app/src/main/java/com/wangzan101/mika/chat/AttachFilesProvider.kt](https://www.google.com/search?q=https://github.com/Ichiro786/Mika/blob/main/app/src/main/java/com/wangzan101/mika/chat/AttachFilesProvider.kt); corroborated by recent commit `efc6748` (*"fix: 等待回答时保留附件的排队模式入口(#531)"*) and open bug report [Issue #482 ("【缺陷】任务运行过程中，对话输入框无法加入图片")](https://github.com/wangzan101/Mika/issues) & [Issue #579](https://github.com/wangzan101/Mika/issues).
* **Evidence from Source Code:** While commit `efc6748` (#531) preserved pre-existing attachments when entering queued mode while waiting for an answer, the composer's attachment picker entry point in `ChatScreen.kt` / `ChatAttachments.kt` remains disabled or inaccessible during active mid-run interjection states.
* **User-Visible Impact:** Mika's core value proposition includes *"Jump in or stop anytime: Keep talking while a task runs to add or correct things"* ([Features Guide](https://github.com/wangzan101/Mika/blob/main/docs/features.en.md)). When a user realizes mid-run that Mika needs a reference photo, QR code, or document to complete the ongoing task, they cannot attach it into the interjection message without stopping the entire task.
* **Recommended Correction:** Decouple the attachment button's `enabled` state in `ChatScreen.kt` from `!isTaskRunning`. Allow `AttachFilesProvider` to stage images/files into `SharedDraftStore` during active runs, and enqueue the attachment payload alongside the text interjection into the active `Run` inbox (`core/run/`).
* **Regression Risk:** Low-to-Medium — requires verifying that `Run` inbox message serialization attaches `SharedFile` references cleanly before the next model turn.
* **Confidence:** Confirmed.

#### `UI-003` — Pre-Expressive Material 3 Dependency (`1.3.1`) and iOS-Modeled Typography Tokens (`MikaType`)
* **Severity:** High

#### Risky Coupling & Regression Points to Guard During Redesign
1. **Self-Operation Tool (`Allow Mika to operate its own UI` / PR #435):** As documented in [`docs/features.md`](https://github.com/wangzan101/Mika/blob/main/docs/features.md) (lines 25–28), when enabled, Mika can programmatically open its own `Settings`, `Browser`, `Memory`, `Plans`, or in-app file viewer pages via `Route` navigation intents. **Constraint:** Any refactoring of `ui/Navigation.kt` MUST preserve the public `Route` enum names and deep-link entry functions used by `self/` (`com.wangzan101.mika.self`).
2. **Compatibility Self-Check Test Page (`ui/SelfCheckScreen.kt` & `selfcheck/`):** As documented in [`docs/setup-guide.md`](https://github.com/wangzan101/Mika/blob/main/docs/setup-guide.md) (lines 240–246), the 12-item Compatibility Self-Check opens Mika's own test page on the virtual display to test screen reading, tapping, typing, scrolling, and back navigation. **Constraint:** Do not alter semantic labels, test tags, or layout coordinates of the self-check target surface inside `selfcheck/` / `SelfCheckScreen.kt`.
3. **Wireless Debugging Pairing Notification & Split-Screen Flow (`PhoneSetupScreen.kt`):** Pairing codes expire immediately if the system pairing dialog loses focus (`docs/setup-guide.md`). **Constraint:** Redesigning `PhoneSetupScreen.kt` must preserve the notification-based pairing input (`POST_NOTIFICATIONS`) and split-screen inline code fallback.
4. **Virtual Display Audio & Orientation Sync (`ScreensScreen.kt`, `PipPhysics.kt`):** Recent releases (`v0.1.36`, `v0.1.37`, `v0.1.38`) and [Issue #483](https://github.com/wangzan101/Mika/issues) highlight delicate interactions between the background virtual display lifecycle, app orientation requests, and foreground media audio focus. **Constraint:** Modifying `PipSizing.kt` or `ScreensScreen.kt` UI chrome must not recreate or tear down the underlying virtual display `Surface` during recomposition.
5. **11-Language String Resource Keys (`app/src/main/res/values*/strings.xml`):** CI runs `tools/i18n/translations.py check` and `StringResourcesTest` across all 11 UI languages (`CONTRIBUTING.zh-CN.md`). **Constraint:** Reuse existing string resource keys whenever possible, and validate any new keys with `python3 tools/i18n/translations.py check`.

### 2. Proposed Target UI Architecture (Claude Duet-Inspired, Zero `:core` Changes)

1. **Design Foundation (`ui/theme/`):**
   * Upgrade `Tokens.kt` (`MikaType`) to a semantic Material 3 Expressive typography scale with tabular numerals (`tnum`) for metrics and distinct editorial display/headline styles.
   * Add a true-black `#000000` AMOLED color scheme in `Colors.kt` (`MikaDarkColorScheme`) with 5 tonal container steps (`#000000` → `#0B0B0E` → `#121217` → `#1A1A22` → `#24242F`), warm terracotta/amber primary accents, and semantic agent state colors (`Running` = Indigo/Cyan, `Needs You` = Amber/Orange `#FF9F1C`, `Completed` = Emerald, `Error` = Coral).
   * Centralize physics springs in `Tokens.kt` (`MikaMotion.SpatialSpring`, `MikaMotion.MicroSpring`, `MikaMotion.DecaySpec`).
2. **Predictive-Back Navigation & Persistent Activity Bar (`ui/Navigation.kt`):**
   * Enhance `NavStack` with `SaveableStateHolder` and `AnimatedContent` driven by `PredictiveBackHandler`.
   * Replace the overloaded left-edge drawer (`ChatDrawer.kt`) with a clean **Top Conversation Header** (left: History & Search Bottom Sheet; center: Model/Mode selector pill; right: New Chat & Capabilities) plus a **Persistent In-App Agent Activity Bar** docked just above the composer whenever background tasks (`TaskService`) or scheduled runs are active.
3. **Streamlined Conversational Workspace (`ui/ChatScreen.kt` & `ui/ChatRows.kt`):**
   * **Empty State:** Editorial greeting + 2×2 tactile suggestion cards (`RecommendedTasksScreen` data) + clean floating composer.
   * **Active/Completed Turn:** Group all intermediate tool calls (`tap`, `type`, `scroll`, `phone_observe`) into a single collapsible **`AgentActivityCard`** with live mini-screen preview (`VirtualDisplayCanvas` using `drawWithCache`) and step counter (`Step N / M`). Tapping expands inline or transitions to `Route.Run` (`RunTimelineScreen.kt`).
   * **Unified Composer:** Enable image/file attachments during active runs (`UI-002`), expose a `+` Capabilities Sheet (Skills, Browser, Files, Sandbox Terminal, Ask/Autonomous toggle), and separate the text input from a dedicated Hold-to-Talk button (`VoiceHold.kt`).
